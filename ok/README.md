# OK

Claude が返答したあと、利用者が次に送りそうな指示を予測して、入力欄のすぐ上にボタンで出す。ボタンを押すと、その指示を入力欄から送ったときと同じくセッションに送る。

```
│ 直しました。テストも通っています。コミットしますか？     │
│ ✦ (①はい、コミットして) (②テストを足して) (③差分を見せて) × │
│ ┌──────────────────────────────────────────────────────┐ │
│ │ Agent への指示を入力...                              │ │
│ └──────────────────────────────────────────────────────┘ │
```

## 出すとき

- 会話の末尾（P13）に出す。入力欄のすぐ上で、会話と一緒にスクロールする
- 出すのは、Gasho から起動した（入力を送れる）Claude Code のセッションが、待機中（`idle`）のときだけ。作業中と確認待ちのあいだは出さない。Codex のセッションには出さない
- 予測は返答ごとに 1 回で、`SessionInfo.lastActivityAt` で返答を見分ける。予測しているあいだは「次の指示を予測しています…」を出す
- ボタンを押して送るか、「×」を押すと、次の返答まで出さない。送れなかったときは、ボタンを残して理由を出す
- 予測できなかったときは、理由と「もう一度」を出す。候補が無かったときは何も出さない

## キーで選ぶ

候補には、左から 1・2・3 の番号を、ボタンの左に出す。番号の数字キーを押し続けると、その候補を送る。押し続ける秒数は設定の `holdSeconds`（既定は 2.5 秒）で、押しているあいだは、番号を囲むリングがその秒数をかけて一周する。

- 先に離すと送らず、リングは空に戻る。候補の無い番号のキー、Ctrl・⌘・Alt と一緒に押したキー、日本語の変換中のキーは使わない
- キーは、画面のどこにフォーカスがあっても読む。ただし、文字の入った入力欄では読まない（数字はその入力欄に入る）
- 空の入力欄（フォーカスのある、空の入力欄）では、押しているあいだ数字を入れない。その秒数より前に離したら、そのときに数字を入れる。「2 で」のように、数字で始まる指示も書けるようにするためである
- 押しているあいだにほかのキーを押したら、押していた数字を先に入れて、長押しをやめる。ウィンドウからフォーカスが外れたら、何もせずにやめる
- ボタンを押したときは、待たずにすぐ送る

## 予測のしかた（daemon の部分）

1. working server の Claude Code の会話の記録（`~/.claude/projects/<フォルダー>/<セッションの ID>.jsonl`、`CLAUDE_CONFIG_DIR` があればその下）の、末尾の 2MB を読む
2. 利用者の発言と Claude の返答の文だけを取り出す。ツールの呼び出しと結果、thinking、サブエージェントの発言、`/model` などのコマンドとその出力、`<system-reminder>` は除く
3. 新しいほうから 8 つの発言を、それぞれ 1500 文字まで（最後の返答だけは、末尾の 8000 文字まで）に切って、Claude Code に渡す。会話が Claude の返答で終わっていなければ予測しない
4. Claude Code は、プラグインのフォルダー（`ctx.dataDir`）の中で、`-p --output-format json` と、ツール・フック・MCP サーバー・スキル・セッションの保存なしで動かす。gasho-daemon はこのフォルダーの Claude Code をセッションとして扱わない（API 1.4）
5. 答えの JSON の配列から、重なりを除いて 3 つまで、それぞれ 200 文字までを返す

同じセッションと返答への予測は、ブラウザーが複数あっても、gasho-daemon のプロセスの中で 1 つの答えを分け合う（新しいほうから 100 件まで覚える）。失敗した答えは覚えない。

## 設定

| キー | 中身 |
|---|---|
| `model` | 予測に使うモデル。`haiku`（既定）か `sonnet`。返答のたびに Claude Code を 1 回動かすので、プランの使用量を使う。すべてのブラウザーで共通 |
| `holdSeconds` | 候補を送るまで数字キーを押し続ける秒数。0.5〜10 秒（0.5 秒刻み）、既定は 2.5 秒。このブラウザーだけの設定 |
