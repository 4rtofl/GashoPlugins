# Better WorktreeList（better-worktree-list）

サイドバーの worktree の一覧に、分け方を2つ足す。「リポジトリごと」は、リポジトリごとのカテゴリ（見出し）の下に worktree を並べる。「作業中・待機中」は、確認待ち・作業中・待機中・オフライン・セッションなしのカテゴリに分ける。分け方は、一覧の見出しの絞り込みのボタン（▤）のメニューの「分け方」で選ぶ。

いまの Gasho のサイドバーは、どのリポジトリの worktree も1列に並べる。リポジトリが多いと、どの worktree がどのリポジトリのものか、どれで Claude が作業しているかが、一目では分からない。このプラグインは、worktree の行とセッション画面の上のタブはそのままに、行をカテゴリに分けて出す。

プラグインの API 1.8 に対応した Gasho が要る（Gasho の PR #62）。サイドバーの worktree の一覧の分け方（P18、`worktreeGroupings`）を使う。Gasho の [docs/plugins.md](https://github.com/4rtofl/Gasho/blob/main/docs/plugins.md) に書いてある。

## 決めたこと

1. 分け方は「リポジトリごと」と「作業中・待機中」の2つ。一覧の見出しのメニューで、「分けない」とあわせて選ぶ。選んだものはブラウザーごとに覚える。まだ選んだことのないブラウザーでは、プラグインを有効にすると「リポジトリごと」になる
2. 「作業中・待機中」のカテゴリは、上から 確認待ち・作業中・待機中・オフライン・セッションなし。確認待ちは、答えの要る worktree をいちばん上に出すために、作業中・待機中と分けた（Gasho のホームのタイルと同じ3つの状態）。セッションの無い worktree は、待機中に混ぜずに「セッションなし」にまとめる。空のカテゴリも見出しだけを出す
3. 分け方と既定の順はこのプラグインが決め、描くのは Gasho である。畳んだ状態と並べ替えた順も、Gasho が分け方ごとに覚える。このプラグインは、daemon の部分も CSS も持たず、権限も要らない
4. 行は、いまの worktree の行のまま（状態の点、見ていない応答のベル、ブランチ名、確認・オフライン）。セッション画面の上のタブも、そのまま残す。行をセッションに置き換える Session List Rewind とは、ここが違う

- 見出しを押すと畳める。畳んだカテゴリにも、開いている worktree の行は出し、見出しには確認待ちの数を出す
- カテゴリも、カテゴリの中の worktree も、ドラッグで並べ替えられる（スマホでは右のつまみ、キーボードでは Alt+↑・Alt+↓）。見出しの「最後に使った順に戻す」で戻す
- リポジトリの絞り込みは、分けているあいだも使える。絞り込んだ worktree だけを分ける
- アイコンだけのサイドバーでは、カテゴリは区切りの線に、畳んだカテゴリは1つのアイコンになる

## 分け方

### リポジトリごと

- カテゴリは、working server とリポジトリのフォルダー（main の worktree のフォルダー）ごとに1つ。同じリポジトリの worktree は、1つのカテゴリにまとまる。同じパスのリポジトリでも、working server が違えば別のカテゴリになる
- リポジトリの外のフォルダーは、working server ごとに1つの「リポジトリの外」にまとめる。フォルダーごとに見出しを作ると、見出しと行が1対1で並び、一覧が長くなるためである
- 見出しはリポジトリ名（GitHub のリポジトリ名か、フォルダー名）。working server が2台以上あるときは、その名前を薄い字で添える。ポインターを乗せると、working server とフォルダーを出す
- 同じ working server で見出しが同じ名前になるとき（fork と upstream を別の clone にしたときなど）は、リポジトリのフォルダーが入っているフォルダーを薄い字で添える（`…/src`・`…/fork`）。その名前も同じなら、見分けがつくまで上のフォルダーまで出す。同じフォルダーに並んでいるとき（`/u/repos/Gasho` と `/u/repos/Gasho-fork` など）は、リポジトリのフォルダー自身の名前を添える。ポインターを乗せたときの説明が出ないスマホの幅でも見分けられるようにするためである
- 添える文字が、ほかの見出しに添える文字と同じ文字で始まるときは、同じ部分を除いて、違い始める位置から出す（`…/GashoPlugins` と `…/GashoPlugins-fork` なら `…/GashoPlugins`・`…-fork`）。区切るのは、`-` などの記号、大文字、数字の位置。Gasho は説明を末尾から省略するので、スマホの幅では説明の先頭しか見えないためである。同じ理由で、working server が2台以上あるときは、その名前を添えるフォルダーの後ろに続ける（`…/src · mac`）
- リポジトリのフォルダーが分からず、リポジトリ名だけが分かる worktree（古い gasho-daemon のセッションと、リポジトリのフォルダーを覚える前の Gasho がブラウザーに覚えた worktree）は、同じ working server にその名前のリポジトリが1つだけあれば、そのカテゴリに入れる。無いか2つ以上あれば、その名前のカテゴリにまとめ、「＋」は最後に使った worktree で起動する。2つ以上あるときは、同じ名前の見出しと見分けられるように、このカテゴリには「フォルダー不明」と薄い字で添える
- 見出しの「＋」は、リポジトリのフォルダー（main の worktree）でセッションを起動する。そのフォルダーがカテゴリの worktree に無いとき（bare のリポジトリなど）は、最後に使った worktree で起動する。「リポジトリの外」には「＋」を付けない
- 行の2行目は出さない。リポジトリ名は見出しにある
- カテゴリの ID は「working server の ID ＋リポジトリのフォルダー」（リポジトリの外は「working server の ID ＋ outside」、リポジトリ名だけが分かるものは「working server の ID ＋ name ＋リポジトリ名」）で、プラグインを更新しても変わらない

### 作業中・待機中

- 次の順に当てはめて、worktree のカテゴリを決める。状態は、Gasho が行の点に使うもの（worktree のセッションのうち、いちばん急ぐものの状態）である
  1. セッションが無い → セッションなし（セッションが終わってブラウザーが覚えている worktree と、登録したリポジトリの worktree）
  2. working server がつながっていない → オフライン
  3. 確認待ち（権限の確認、質問への回答、計画の承認を待っている）→ 確認待ち、Claude が作業している → 作業中、それ以外 → 待機中
- 見出しの並びは、上から 確認待ち・作業中・待機中・オフライン・セッションなし。空のカテゴリも見出しだけを出す。Gasho は、並べ替えたときに出ていたカテゴリの順だけを覚え、あとから出たカテゴリを先頭に出すので、空のカテゴリを出さないと、空だったカテゴリが中身ができたときに先頭に出てしまう。「＋」は付けない
- 行の2行目は、いまの一覧と同じリポジトリ名（working server が2台以上なら、その名前も）
- バックグラウンドでシェルだけが動いているセッションは、Gasho と同じく待機中にする。開発サーバーのように終わらないものがあるためである。サブエージェントが動いているあいだは作業中
- カテゴリの ID は `waiting`・`busy`・`idle`・`offline`・`none` で、変えない

## 並べ方

- カテゴリの中の worktree は、最後に使った順（セッションの最後の会話の記録の時刻、無ければ起動した時刻）。セッションの無い worktree は後ろに、Gasho の順（登録したリポジトリのもの、ブラウザーが覚えているものの順）で並べる。Gasho の一覧の「最後に使った順」と同じである
- 「リポジトリごと」のカテゴリは、その中のいちばん最後に使った worktree の順。セッションの無い worktree だけのカテゴリは、その後ろに並べる
- ドラッグで並べ替えると、Gasho がその順を分け方ごとに覚えて、この順の上に当てる。並べ替えたあとに増えたカテゴリと worktree は先頭に出る
- 1.0.0 で「作業中・待機中」を並べ替えた順には、そのとき出ていたカテゴリしか入っていない（1.0.0 は空のカテゴリを出さなかった）。そのため 1.0.1 に更新した直後は、そのとき空だったカテゴリが先頭に出る。並べ替え直すか、見出しの「最後に使った順に戻す」を押すと、5つのカテゴリの順を覚え、そのあとは起きない
- Claude が作業を始めたり終えたりすると、「作業中・待機中」では worktree がカテゴリを移る。ポインターがサイドバーの一覧の上にあるあいだ（スマホではドロワーを開いているあいだ）は、Gasho が並びも、worktree がどのカテゴリにあるかも止める。押す前に行が動いてしまうためである。行の点とバッジは変わる

## 確かめたこと（2026-11-15）

Gasho の変更（API 1.8、Gasho の PR #62）の worktree から試しの Gasho サーバーを動かし、このプラグインを `plugin add --link` で入れて、ヘッドレスの Chrome（CDP）で確かめた。working server には仮の gasho-daemon をつないだ。仮の gasho-daemon は、3つのリポジトリ（Gasho は worktree が2つ）、リポジトリの外の2つのフォルダー、セッションの無い登録したリポジトリ（Daichoo）のセッションを報告し、制御用のポートでセッションの状態を変え、セッションを消し、通知を起こす。

- はじめて開いたブラウザーで「リポジトリごと」が選ばれ、GashoPlugins → Gasho → Bobert → リポジトリの外 → Daichoo（セッションなし）の順に並んだ。リポジトリの見出しには「＋」が付き、「リポジトリの外」には付かず、行に2行目は出なかった
- メニューの「分け方」で「作業中・待機中」に切り替えると、確認待ち（Bobert）・作業中・待機中・セッションなし（Daichoo）に分かれ、行の2行目にリポジトリ名が出た。「分けない」に戻すと、いまの一覧になった
- ポインターが一覧の外にあるとき、セッションを作業中にすると、その worktree が待機中から作業中へ移った。ポインターを一覧に乗せたまま、確認待ちのセッションと作業中のセッションを待機中にすると、行は元のカテゴリに留まり（点は灰色に、「確認」は消えた）、ポインターを離すと待機中へ移り、空になった確認待ちは消えた（1.0.1 から、空のカテゴリも見出しだけを出す）
- 確認待ちと作業中を畳むと、確認待ちの見出しに「確認 1」が出て、作業中には開いている worktree の行が残った。畳んだ状態は分け方ごとに覚えた
- カテゴリのドラッグ、カテゴリの中の行のドラッグ、Alt+↑、「最後に使った順に戻す」が動いた
- 「リポジトリごと」の Gasho の「＋」で、main の worktree にセッションが起動して開いた
- 1つしかないセッションを消した worktree（notes）は、ブラウザーが覚え、「セッションなし」に移った
- working server を2台にすると、同じパスの Gasho が「Gasho · mac」「Gasho · devbox」の2つのカテゴリに分かれ、「作業中・待機中」では行の2行目に working server の名前が付いた
- 390px の幅では、ドロワーにカテゴリが並び、見出しと行にタッチ用のつまみが出た。ドロワーを開いているあいだはセッションを作業中にしても行は移らず、閉じて開き直すと移った
- ページを3回読み込み直し、ページの最初から見張っても、分けない一覧は一度も出なかった
- プラグインを無効にすると、読み込み直さずにいまの一覧に戻り、メニューから「分け方」が消えた。有効に戻すと、選んでいた分け方で分かれた
- 「リポジトリごと」のフックがエラーを投げる版にすると、いまの一覧と「Better WorktreeList の分け方を使えないので、worktree を分けずに並べています」の知らせが出て、プラグインの画面に理由が出た。そのまま「作業中・待機中」には切り替えられた。直した版に入れ替えると、読み込み直さずに「リポジトリごと」に戻った
- Session List Rewind を入れると、サイドバーはセッションの一覧になり、このプラグインのカードに「Session List Rewind がサイドバーをセッションの一覧にしているので、worktree の分け方は使っていません。」と出た。外すと分けた一覧に戻った
- 見ていない応答のあるセッションの worktree は、分けた一覧でも行にベルが出た（Gasho の #61）

## ファイルの構成とテスト

```
better-worktree-list/
├─ gasho-plugin.json       api 1.8、web だけ（daemon の部分も CSS も無い）
├─ package.json            build は gasho-plugin build、dev は gasho-plugin build --watch
├─ tsconfig.json
├─ src/web/
│  ├─ index.tsx            worktreeGroupings：「リポジトリごと」と「作業中・待機中」
│  ├─ repo.ts              リポジトリごとのカテゴリ
│  └─ status.ts            状態ごとのカテゴリ
└─ test/
   ├─ repo.test.ts
   └─ status.test.ts
```

- `repo.test.ts`：カテゴリと worktree が最後に使った順になること、カテゴリの ID、「＋」で起動する worktree の選び方（main の worktree、無ければ最後に使ったもの）、リポジトリの外が working server ごとに1つになること、working server ごとに分かれて名前が付くこと、リポジトリ名だけが分かる worktree の入れ先、同じ名前の見出しに添えるフォルダー
- `status.test.ts`：カテゴリの決め方（セッションなし、オフライン、確認待ち、作業中、待機中の順）、見出しの並び、空のカテゴリも出すこと、行の2行目を Gasho に任せること

## 今回は扱わないこと

- 2つの分け方を重ねること（リポジトリの中を状態で分けるなど）。サイドバーのカテゴリは1段である
- 行を別のカテゴリへドラッグで動かすこと。カテゴリはリポジトリか状態で決まる
- 見ていない応答（ベル）があるかで分けること。分け方の文脈は、まだそれを渡していない
