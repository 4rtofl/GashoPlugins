# Worktree Status（worktree-status）

サイドバーの worktree の一覧に、分け方「手で決めた状態」を足す。見出し（進行中・レビュー待ちなど）は、プラグインの設定で自分で作る。worktree の行を見出しへドラッグすると、その見出しに入る。分け方は、一覧の見出しの絞り込みのボタン（▤）のメニューの「分け方」で選ぶ。

Better WorktreeList の「作業中・待機中」は、セッションの動きから見出しが自動で決まる。このプラグインは、Orca のワークスペースの一覧のように、作業がどこまで進んだかを自分で決めて、worktree を見出しに入れる。

プラグインの API 1.9 に対応した Gasho が要る（Gasho の PR #70）。サイドバーの worktree の一覧の分け方（P18、`worktreeGroupings`）の `useOnMove` と、すべてのブラウザーで共通の値（`useSharedState`）を使う。Gasho の [docs/plugins.md](https://github.com/4rtofl/Gasho/blob/main/docs/plugins.md) に書いてある。

## 決めたこと

1. 分け方は「手で決めた状態」の1つ。見出しは、設定の画面のこのプラグインの区切りで、足す・名前を変える・並べ替える（↑・↓）・消す。はじめは「進行中」「レビュー待ち」の2つ
2. 見出しと、worktree を入れた見出しは、Gasho サーバーに保存する（`useSharedState` の `headings` と `placed`）。ページを読み込み直しても、別のブラウザーで開いても同じになる。見出しの中の worktree の順と、見出しの並べ替えた順・畳んだ状態は、Gasho がブラウザーごとに覚える
3. どの見出しにも入れていない worktree（新しく作ったものを含む）は、Gasho が最後に足す「その他」に並ぶ。見出しを消すと、そこにあった worktree は「その他」に戻る。行を「その他」へドラッグしても、見出しから外れる
4. 行の無い見出しも出す。出ていない見出しには、行を落とせないためである
5. 描くのは Gasho である。このプラグインは、daemon の部分を持たず、権限も要らない。CSS は設定の画面の部品のためだけにある

## 画面

```
サイドバー（手で決めた状態）              設定の画面（Worktree Status の区切り）
┌────────────────────────────┐       ┌──────────────────────────────────────┐
│ worktree           ▤ ↺ ＋ │       │ [進行中          ] ↑ ↓ 消す          │
│ ˅ 進行中                   │       │ [レビュー待ち    ] ↑ ↓ 消す          │
│   ● feat/106-worktree-st…  │       │ [新しい見出しの名前] ＋見出しを足す   │
│     GashoPlugins           │       └──────────────────────────────────────┘
│ ˅ レビュー待ち             │
│   ● feat/64-move-category  │
│     Gasho                  │ ← 行を別の見出しへドラッグすると入る
│ ˅ その他                   │ ← どこにも入れていない worktree
│   ● main                   │
└────────────────────────────┘
```

- 行のドラッグは、PC では行そのもの、スマホでは右のつまみ、キーボードでは見出しの先頭・最後の行で Alt+↑・Alt+↓
- 行の2行目は、いまの一覧と同じリポジトリ名（working server が2台以上なら、その名前も）
- 見出しの名前は、欄から離れたとき（Enter を含む）に保存する。空にしたときは、前の名前に戻す。Gasho は名前の無いカテゴリを出さず、その worktree を「その他」に移すためである。Esc で、書きかけを前の名前に戻す
- 保存できなかったとき（Gasho サーバーが断ったとき）は、設定の画面に理由を出す。行のドラッグで保存できなかったときは、Gasho が行を元に戻し、一覧の見出しの下に理由を出す

## 覚え方

- `headings` は見出しの配列（`{ id, title }`）で、並びが見出しの既定の順になる。ID は名前を変えても変わらない（Gasho は、並べ替えた順と畳んだ状態を、カテゴリの ID で覚える）
- `placed` は、worktree の `key`（working server の ID とフォルダー）から見出しの ID への対応で、最後に入れたものが最後に来る
- worktree を消しても、`placed` にはその worktree が残る。`placed` の値は 64KB まで（worktree 1つでおよそ 100 バイト）なので、300 を超えたら、サイドバーに出ていない worktree のうち、入れたのがいちばん古いものから忘れる。リポジトリの絞り込みで出ていない worktree も、ここでは出ていないものとして数える

## 確かめたこと（2026-11-16）

Gasho の変更（API 1.9、Gasho の PR #70）の worktree から試しの Gasho サーバーと gasho-daemon を動かし、その worktree で作った SDK でビルドしたこのプラグインを `plugin add --link` で入れて、Chrome で確かめた。リポジトリ（Gasho）を登録して、セッションの無い worktree を並べた。別のブラウザーの代わりに、ホスト名を変えたタブ（Cookie と localStorage が別になる）を、別の端末として登録して使った。

- 分け方を「手で決めた状態」にすると、「進行中」「レビュー待ち」（行なし）と、すべての worktree の入った「その他」が出た。途中で新しく作られた worktree も「その他」に出た
- 行を「その他」から「進行中」へ、「レビュー待ち」へ、行の無い「完了」へドラッグすると、その見出しに入り、Gasho サーバーの `placed` に保存された。「その他」へドラッグすると、見出しから外れた
- ページを読み込み直しても、別の端末として登録したタブで開いても、同じ見出しに入っていた。片方のタブで見出しを変えると、もう片方にも読み込み直さずに出た
- 設定の画面で、見出しを足す（Enter）、名前を変える（行は名前を変えた見出しに残った）、↑ で並べ替える、消すが、サイドバーにすぐ出た。見出しを消すと、そこにあった worktree が「その他」に戻り、`placed` からも消えた。名前を空にして Enter を押すと、前の名前に戻った

## ファイルの構成とテスト

```
worktree-status/
├─ gasho-plugin.json       api 1.9、web と CSS（daemon の部分は無い）
├─ package.json            build は gasho-plugin build、dev は gasho-plugin build --watch
├─ tsconfig.json
├─ src/web/
│  ├─ index.tsx            worktreeGroupings の「手で決めた状態」と、設定の画面の部品
│  ├─ headings.ts          見出しのカテゴリ、行を落としたときと見出しを消したときの placed
│  ├─ settings.tsx         設定の画面の、見出しの一覧
│  └─ style.css
└─ test/
   └─ headings.test.ts
```

- `headings.test.ts`：見出しの順にカテゴリが並び、行の無い見出しも出ること、入れていない worktree と消した見出しにあった worktree を返さない（「その他」に任せる）こと、行を落とすと見出しが変わり「その他」へ落とすと外れること、300 を超えたら出ていない古いものから忘れること、見出しを消すとその worktree が外れること

## 今回は扱わないこと

- お気に入り（Orca の星）と、Pull request の状態で分けること
- 見出しの中の worktree の順を、すべてのブラウザーで同じにすること。順は Gasho がブラウザーごとに覚える
